# Architectural decisions

Status: ACTIVE. The index of the decisions the code rests on. The full journal (no. 1–189, including game
design) is the «Decision journal» table in the library's `plan/README.md`; the numbers below are from it. A
new decision is written into the journal first, and here — if it changes a principle of the code. Where the
reason is not recorded, it says so. A Russian copy: [DECISIONS_RU.md](DECISIONS_RU.md).

| Decision | Problem | Reason | Consequences | Status | Where |
|---|---|---|---|---|---|
| Godot 4, GDScript only (no. 1) | an engine for web, Android, PC and the server | GDScript works in all target builds; there is no C# in Godot 4's web export | hot spots of the server — GDExtension if needed; in the browser only GDScript | in force | `plan/architecture/overview.md` |
| The Compatibility renderer, web without threads | the game in a phone's browser | WebGL 2; without threads the hosting needs no COOP/COEP headers | no heavy effects (SDFGI, volumetric fog); a limit of lights per object; shaders are warmed up by hand | in force for web and PC; Android draws with the Mobile renderer through Vulkan (no. 188) | `project.godot`, `plan/architecture/overview.md`, [systems/rendering.md](systems/rendering.md) |
| An authoritative server, WebSocket, mods only on the server (no. 2) | multiplayer | honesty: the client sends intentions, the server decides | the rules are separate from the client; the client sends protocol requests, the server decides | in force (the server is built by decision 153) | `plan/architecture/server.md`, [systems/network.md](systems/network.md) |
| Code by layers `src/shared/` and `src/client/` (no. 116, PR #57–#64) | the rules were in the client | the server must run the same rules | shared loads no client (a test); a rule takes `who` and reports by signals | in force | [ARCHITECTURE.md](ARCHITECTURE.md) |
| `preload` constants, no `class_name` | how scripts find each other | the reason is not recorded | moving a file is an edit of paths; a return typed with its own script is not written | in force | all `.gd` |
| A world without an edge, a deterministic generator (no. 60) | the 1024×1024 island was too small | everything comes from noise at the column itself: a chunk is made in any order and again the same | far untouched chunks are forgotten; only the changes are saved | in force | [systems/world-generation.md](systems/world-generation.md) |
| Nothing the size of a chunk per frame | freezes on a phone (the browser is ~10 times slower than PC) | a smooth frame matters more than loading speed | jobs by columns and rows within budgets; `frame_test` in CI | in force | [systems/chunks.md](systems/chunks.md), `plan/architecture/performance.md` |
| Saving only what changed (no. 64, PR #31) | the size of saves, IndexedDB in the browser | the world is made again from the seed | a folder per world; the modules give their part (`to_dict`); conversions of old versions in `save_game.gd` | in force | [systems/saving.md](systems/saving.md) |
| Content is a mod's data in YAML, our own parser (no. 58) | content constants in the code | one format for the game, the server and the validator, later the editor | schemas in `content.gd`; the validator in CI; content numbers are not in code | in force | [DATA_MODEL.md](DATA_MODEL.md) |
| Content by roles, not by id (no. 140) | the engine named the mods' records | a mod with other species or tools replaces them with no code edit | by id only the core; roles are closed lists of the schema | in force | [DATA_MODEL.md](DATA_MODEL.md) |
| Mods divide into bundles, dependencies from references (no. 139, 146, PR #161, #173–#178) | all or nothing by mods | each entity can be switched off; a world is assembled only from what works | a world's set of bundles is fixed; material numbers by loading order | in force | [DATA_MODEL.md](DATA_MODEL.md) |
| Pictures, models, sounds are the mods' files (no. 141–143) | pictures and sounds were drawn by code | the data is replaceable by a mod, the code is not touched | drawing tools and synthesis in `tools/`; a sound by name, the last mod wins | in force | [DATA_MODEL.md](DATA_MODEL.md) |
| Big files split by inheritance (no. 145, PR #168–#172) | files of 1500–2800 lines | read and change by topic | a base script + heirs through `extends "res://…"`, the calling code did not change | in force | `chunk_mesher.gd`, `world_gen.gd`, `world_data.gd`, `tools/shot.gd`, `tests/unit/`; no. 168 (2026-11-05): `world_actions.gd`, `content.gd`, `main_menu.gd`, `hud.gd` — chains of parts, each calls only itself and the earlier ones |
| The version `<stage>.<PR>` and the «What's new» lines (no. 118, PR #68) | the player sees what changed | — | every PR has a line «Что нового [вид]: …» | in force | [systems/testing.md](systems/testing.md) |
| The check in a browser only for changed files (no. 131, PR #110) | a long CI | software WebGL is slow | the template `web` in `build.yml`, the label `smoke` | in force | `.github/workflows/build.yml` |
| The code's documentation in the repository's `docs/` (no. 151, stage 0, 2026-10-30) | the description of the code in four places diverged | a document is edited in the same PR as the code and checked by CI | `plan/` in the library — game design, decisions, stages | in force (option A, picked by the user 2026-10-30) | [INDEX.md](INDEX.md), [audit/AUDIT_REPORT.md](audit/AUDIT_REPORT.md) |
| The game's bundle system by the spec `bundles.md` (no. 152, 2026-10-30) | the spec asks for entities with links, recipes, chains and the check of dead ends | extend the present data model rather than build a second mechanism; the user's answers 1А, 2В, 3А, 4А | the spec's entity is a record `mod:name`, a bundle stays a part of a mod; there are no technologies, eras are labels the graph checks; stations and tools are open classes and flags; a supplementing bundle enters an old world | accepted, built (stages 1–8, PR #238–#248) | [specifications/BUNDLE_SYSTEM.md](specifications/BUNDLE_SYSTEM.md) |
| A server by the same executable, a world session with a tick (no. 153, 2026-10-31) | an authoritative server is needed with a client in the browser, on Android and PC | one code of the game and the server: the server is the same game without a window or «Create a server» in the menu; the rules over the world are run by the session (`session.gd`), the server sends the client ready chunks, the client moves its own body under the server's check, mods are only built-in, a server on one's own PC through a Cloudflare Tunnel | the client holds a copy of the world; single player is a server in the same process (`local_host.gd`) | in force (stages С1–С7, PR #249–#263) | `plan/architecture/server.md`, [systems/session.md](systems/session.md) |
| Building by things on cells and by blueprint (no. 163, PR #335–#339, #371, #372) | walls, doors, stairs, furniture | the new is data: a thing on cells with an item's flags (`steps`, `door`, `window`, `furniture`, `seat`, `keeps`), the size by the model's slice, turned to face the player; the blueprint is a rule of the session | doors, windows, stairs, furniture and a fireplace are `tools` records; a blueprint is stored with the world (`plans`); pitched roofs — by a block's shape; a fence, wicket, gates, 3×3 gates, 1×1 and 2×2 hatches, a leaning ladder — stage 1, item 5 (`fences_test`) | in force | [systems/crafting.md](systems/crafting.md), [systems/interaction.md](systems/interaction.md) |
| Skills as data (no. 164, PR #340–#342) | work must teach and speed up | a skill is a record of the kind `skills`, the engine asks for it by the work's role; the experience is given by the rules that know the work is useful | 10 skills in `core`; speed, extra yield, durability, reserve of ground from levels; recipes are not closed by skills | in force | [systems/character.md](systems/character.md) |
| Farming on a bed (no. 169, PR #387, #388, #390) | crops must grow by time and weather, not per frame | a bed is a cell material, a crop is fields of a bed's cell; growth is a step of the session by season and moisture | new crops are `plants` records with a crop role; farm mode is built like build mode | in force | [systems/interaction.md](systems/interaction.md) |
| The tool decides the blow, the skill the hand (no. 170, PR #395) | a skill and a tool gave the same thing | the strength of a blow is the tool's data and the cell's `toughness`, the skill is pace, strength, extra yield, care | numbers in the mods' YAML and `docs/balance/`; wear is on by default | in force | [balance/GAME_BALANCE_DESIGN.md](balance/GAME_BALANCE_DESIGN.md) |
| The cave view by layers (no. 165, 168; PR #345–#368) | the slice of levels cut away what stood behind and below the player in caves | only the quarter of the view in front of the player above the line melts away by dither, the rest stays; the void is closed by a cut of rock in dots | one cave view (the old modes are gone, decision 168); the depth darkens 12 % a level below the sea, the fires' light lifts it back | in force | [systems/rendering.md](systems/rendering.md) |
| Testing and CI by levels (no. 166, PR #346, #370) | slow, tangled checks | quick checks without the game first (`lint.py`, `parse_check.gd`, the pre-commit hook), property tests, `progress_test` in two halves, CI jobs by level, actions pinned by SHA, Godot checked by SHA-512 | idle in `frame_test` is judged by a share of a chunk, not stricter than a floor (1.25 ms by day, 1.55 ms at night by a fire) | in force | [testing/CI_PIPELINE.md](testing/CI_PIPELINE.md), [systems/testing.md](systems/testing.md) |
| Loading the world and warming shaders (no. 173, PR #379, #381, #384) | the first frames froze compiling shaders | light mixes without the sun are not built (the sun is never off), fires' shadow mixes only with real shadows, the night set is warmed when the time of day needs it; unlit things on their own layer the fires do not touch | a new kind of light or a material shown later goes into `shader_warmup.gd` | in force | [systems/rendering.md](systems/rendering.md) |
| Seasons and saplings (no. 175, PR #397) | how long plants and seasons take | the user's pick | a season is 14 days; a sapling grows into a shoot, then a young tree that gives only branches, then a grown one | in force | [systems/time-weather.md](systems/time-weather.md), [systems/interaction.md](systems/interaction.md) |
| Build mode, a slope as a cell's shape (no. 171, PR #380–#394) | building got in the hands' way, slopes were things | one builds only in one's own mode (palette, shapes, height); a slope, an inverted slope and steps are a cell's shape in the world's data | a blueprint by shape is a rule of the session; the mesh and collisions know the cells' shapes | in force | [systems/interaction.md](systems/interaction.md) |
| The server trusts nothing (no. 172, PR #377) | a cheater sends a socket what they like | every request checks types, bounds, reach, land rights and pace | the rules for new requests are in `CLAUDE.md`; the checks in `security_test.gd` and `server_test.gd` | in force | [security/THREAT_MODEL.md](security/THREAT_MODEL.md) |
| Fence, gates, hatch, ladder (no. 182, PR #450) | building lacked pens, gates and ways up | a fence is a thin link in the middle of a cell that joins its neighbours, solid 2 cells high (above a jump), and beasts do not step over things above one and a half cells; a wicket and gates are doors in the fence's line; a hatch is a lid in a built floor or ceiling; a ladder is a link a cell, with no falling on it | built by blueprint in build mode; fence, wicket, gates, ladder by hand from branches and rope, hatches and 3×3 gates from boards at a workbench | in force | [systems/crafting.md](systems/crafting.md), [systems/interaction.md](systems/interaction.md) |
| The quality of things (no. 181, PR #443) | things of one recipe were all alike | a number 1–100 at a stack (`quality.gd`): what is gathered — from the tool and skill, what is made — from the materials with the ceilings of skill, station and recipe | the ceilings are data (`quality_cap`); old saves — 50 | in force | [systems/crafting.md](systems/crafting.md) |
| Hot reload of mods (no. 184, PR #457) | editing a YAML needed a restart | `content_watch.gd` watches `content/` within a budget per step, `mod_reload.gd` rereads the registries, pictures, sounds; the server — `reload` | only when run from the project folder; cell materials, biomes, relief — in a new world | in force | [systems/content.md](systems/content.md) |
| The server sends its mods' files (no. 189) | a game with other mods than the server's could not join it | a set of bundles is named by one hash of its files (`mod_files.gd`); at `hello` the hashes are compared, a game that lacks files takes them by hash over the same link (`content_host.gd`, `mod_fetch.gd`), keeps them by hash (`mod_cache.gd`) and reads the mods through a table path → file (`Content.serve`); the server's `reload` reaches the games in the world | mods' files are read only through `Content` (`real`, `text`, `files_at`); what a server sends is data of three kinds, each checked; exports carry the list of the built-in files (`content_files.bin`); on a phone one's own mods lie in a folder of the app laid over the built-in ones (`ModFiles.extra_dir`); the protocol is version 2 | in force | [systems/network.md](systems/network.md), [systems/content.md](systems/content.md), [security/NETWORK_SECURITY.md](security/NETWORK_SECURITY.md) |
| Stage 1 closed, the version is 0.3.&lt;PR&gt; (no. 187, 2026-11-11) | when a stage is over and what the version says | the phone pass and the playtest server with bots (`playtest.yml`) were done | the client's version is `<stage>.<PR>` (`project.godot` and `tools/build_info.py`); a release per merge into main | in force | [systems/testing.md](systems/testing.md), `CLAUDE.md` |
| Android draws with Vulkan (no. 188, PR #544) | the OpenGL ES driver of an Adreno 840 crashed the app on any big shader | under Vulkan every step passed | the renderer Mobile on Android, Compatibility in the browser and on PC; a phone without Vulkan falls back to OpenGL; shaders are written for both: colour hints `SRGB`/`SRGB_HINT`, `COMPAT_ALBEDO` at the end of fragment(), `compat_sun` | in force | [systems/android.md](systems/android.md), [systems/rendering.md](systems/rendering.md) |
| Signs (no. 183, 2026-11-08) | players need to leave inscriptions in the world | a sign is a thing on cells with the field `sign_lines` (`sign_width`, `wall` — onto a wall); the text is stored in the thing's record (`text`), written and turned by whoever can build (`Placed.write`, `turn_sign`, the requests `sign_write`, `sign_turn`); a changed sign is placed anew, the copies recognise it as a new thing, with no event of its own; the text above a sign is seen within `Placed.SIGN_READ` 3 cells (`sign_labels.gd`) | in force (PR #452) | [systems/crafting.md](systems/crafting.md) |
| Gestures (no. 183, 2026-11-08) | to agree silently with other players | eight gestures as a list in the code (`gestures.gd`), not as a mod's data: each needs its own columns of the character sheet; a gesture is the character's state on the server (`gesture`, until `gesture_until`), goes to the others in the `people` record, ends on movement and work; one's own plays at once, without waiting for the server | in force (PR #453) | [systems/character.md](systems/character.md) |
| Ten languages, text is a key (no. 183, 186; 2026-11-08, 2026-11-11) | a game for the whole world, English by default | a text for a player is a key in brackets `[bag_is_full]` in the code and in mods, for a record `[<mod>.<kind>.<id>]` (no. 186, option Г), each language, English too, gives it a text; a translation is `lang/<code>.yaml` in a mod and a bundle beside the data; the server does not translate but sends a phrase or `Lang.line` (a template and values in JSON), the client translates itself | a mod brings its own translations; a new key without English or Russian is a red CI (`lang_check.py --strict en,ru`); gluing phrases is forbidden | in force | [systems/lang.md](systems/lang.md) |

## Проблемы найдены и исправлены

1. `progress_test` у предела времени и самый долгий путь CI — поделен на две половины.
2. Ожидания `progress_test` по часам при кадрах в секунды — теперь и по кадрам.
3. Провал `progress_test` при охоте без данных для разбора — сообщение называет место и туши.
4. Прогоны `main` отменялись следующим слиянием — больше нет.
5. Права записи Pages у заданий с кодом PR — только у `deploy`.
6. Плавающие теги actions, Godot без сверки сумм — закреплены и сверяются.
7. Логи терялись — артефакты и сводка.
8. Скрипты, которые не грузит ни один тест, не проверялись — `parse_check`.

## Оставшиеся ограничения и риски

- **Idle в `frame_test` остаётся у предела.** Части кадра простоя теперь видны: в прогоне PR кадр
  простоя — 0,99 мс кода игры (игрок 0,40, животные 0,20, небо 0,12, звук 0,06 …) при пределе 1,05
  (1/20 чанка в 20,9 мс), у костра 1,30 при 1,32. Это не шум: код, идущий каждый кадр, дорос до
  предела (на телефоне это ~10 мс кадра). На машине с чанком 14–17 мс проверка будет падать, пока
  кадр простоя не станет дешевле. Пользователь выбрал ускорить кадр простоя: PR #347 (поиск земли под
  ногами в 2,7 раза быстрее, решения зверей по нужным видам, снимок только шагнувших зверей) — после него
  в `main` 0,61 мс при пределе 0,73 на быстрой машине (чанк 14,6 мс), запас около 1/6.
- Правило ветки (required checks) не включено: его ставит владелец репозитория.
- `actions/*` на Node 20 — предупреждения; обновление majors — отдельно (план, п. 3).
- Кадры 2–6 с после переноса игрока далеко (`progress_test`) не разобраны (план, п. 2).
- Покрытие строк не меряется (нет инструмента без плагинов); покрытие — по сценариям
  ([../testing/TEST_COVERAGE.md](../testing/TEST_COVERAGE.md)).
- Графику, FPS телефона и звук автоматически не проверить; ручные проверки — там же.

# Языки

Статус: ACTIVE.

**Назначение.** Игра на десяти языках (решение 183): английский, русский, испанский, португальский,
французский, немецкий, итальянский, польский, турецкий, украинский. Английский по умолчанию, при первом
запуске — язык устройства, если он есть в списке; переключатель «Язык» первым в настройках, вкладка «Игра».

**Файлы**
- `src/shared/content/lang.gd` — список языков (`LANGS`), таблица перевода (`Lang.Table`, наследник
  `Translation`), `use(code)` ставит язык, `of_device()`, `files`/`read`/`phrases` — файлы `lang/` модов,
  `line(шаблон, значения)` — строка со значениями для сервера, `f(шаблон, значения)` — то же сразу на
  языке игрока (клиент), `t(фраза)` — перевод фразы или строки `line` в коде, `drop()` — снять таблицу
  перед выходом.
- `src/client/settings.gd` — `language` (по умолчанию язык устройства), `use_language`, `set_language`;
  «Сбросить» язык не трогает; `Settings.language_override` ставят тесты (`"ru"`).
- `src/client/ui/settings_menu.gd` — строка «Язык».
- `tools/lang_check.py` — какие фразы кода и контента есть в файлах языка: `--missing <код>` — список
  непереведённых, `--write <код>` — дописать их в файлы с пустым значением, `--strict <код>` — ошибка,
  если чего-то нет (CI, `lint`).

**Данные.** Язык исходников — русский: фраза в коде и `title`/`description` записи в YAML и есть ключ.
Перевод — `lang/<код>.yaml` рядом с данными: `content/core/lang/` — интерфейс и ядро, `content/<мод>/lang/`
и `content/<мод>/<бандл>/lang/` — названия и описания своих записей. Формат — плоский словарь
`"фраза": "перевод"`. Файлы читаются через `Content._read`, поэтому идут и из `content_cache.bin`.
Пустой или отсутствующий перевод — показывается английская фраза (`Table.fallback`), а нет и её — русская.

**Правила**
- Сервер не переводит: правило отдаёт фразу или `Lang.line(шаблон, [значения])` — строку
  `"\u001e" + JSON [шаблон, значения…]`; клиент разворачивает её таблицей перевода (Label, Label3D,
  кнопки — сами, через автоперевод Godot) или `Lang.t` в коде. Значения-строки тоже переводятся
  (названия вещей). JSON, а не `str_to_var`: строку может прислать чужой сервер.
- Клиентский шаблон со значениями — `Lang.f(шаблон, значения)`, не `шаблон % значения`: переводится шаблон,
  потом подставляются значения. Склейку фраз из кусков не делать: у языков другой порядок слов.
- Числительные — отдельными фразами на каждый случай (`"день"`, `"дня"`, `"дней"`), как в русском.
- Журналы и консоль сервера (`print`, `push_warning`, `server_main.gd`, `console.gd`, `tunnel.gd`,
  `real_weather.gd`, `content_graph.gd`) не переводятся; `lang_check.py` их пропускает.
- Новая фраза в коде или новая запись — перевод в `en.yaml` того же места (`python3 tools/lang_check.py
  --write en`, затем заполнить), иначе CI красный. Остальные восемь языков CI не требует (до перевода
  фраза идёт по-английски), но `lang_check.py` без ключей показывает, скольких фраз им не хватает;
  `--write <код>` дописывает их пустыми.
- Перевод держит спецификаторы `%s`, `%d` в том же порядке, что шаблон (`%` в Godot только позиционный),
  иначе `lang_check.py` даёт ошибку для любого языка; `%%` можно переставлять (турецкое `%%%d`).
- Кавычки внутри перевода — «ёлочки» или “лапки” по обычаю языка, не ASCII `"`.

**Подводные камни**
- Скриптовый `Translation` в `TranslationServer` роняет движок при выходе: `Main._exit_tree` зовёт
  `Lang.drop()`, тесты — тоже.
- Строку `line` нельзя сравнивать с фразой: тесты сравнивают `Lang.t(сказанное)` с `Lang.t(ожидаемым)`.
- Длинные английские слова не влезают в узкие полосы: названия навыков короче, полоса обрезает с «.».

**Тесты.** `tests/unit/lang_test.gd` (таблица, `line`/`f`/`t`, файлы модов),
полнота английского — `tools/lang_check.py --strict en`; сцены тестов играют по-русски (`language_override`).

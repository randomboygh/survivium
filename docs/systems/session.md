# Сеанс мира и правила игры

Статус: ACTIVE (этапы С1–С2.3 сервера, решение 153; план `plan/architecture/server.md`).

**Назначение.** Одна точка, которая держит мир с правилами над ним и персонажей в нём и делает тик: то,
что на сервере будет крутиться 20 раз в секунду, а в одиночной игре крутит узел сервера под корнем дерева
перед кадром клиента. Сеанс же заказывает мир: генерирует чанки вокруг каждого игрока в бюджете и
забывает дальние; клиент только строит меши того, что сделано. Правила игры, которые хозяин сервера
задаёт всем (свободная стройка, износ, мгновенный крафт), — отдельный объект, который правила читают
как есть.

**Файлы**
- `src/shared/game/session.gd` — сеанс: берёт мир, генератор, часы, правила и вещи на клетках, сам делает
  `WorldActions`, `Storms`, `Wildlife`; `add_player(who, workshop)` / `remove_player(who)` (персонаж
  получает мир, часы и вещи; звери видят персонажей как людей); `start_wildlife(seed)`; `tick(delta)` =
  `step_clock` (время и погода; погода чувствуется у первого игрока, пока нет климата по районам) →
  `step_players` (каждый персонаж и его мастерская, шаг не больше `STEP_MAX` 0,05 с) → `step_things`
  (поставленный свет догорает, `Placed.step`) → `step_wildlife`
  (на зверей на экранах игроков смотрят — `look_from` по `Character.view_right` / `view_half`, круг
  `Wildlife.NEAR` без экрана; они ходят каждый шаг, остальные раз в 0,1 с) → `step_storms` (ветер вокруг игроков по очереди); `push_on(who)` — чем звери толкнули игрока,
  берётся один раз (линк шлёт событием `push`). Мир вокруг игроков: `zones()` — чанк каждого игрока и
  первая точка возрождения мёртвого; `make_chunks(near_us, far_us, reach)` — генерирует чанки в `reach`
  (`ZONE` 5) от зон по шагу задания в бюджете (`near_us`, пока чанк в `NEAR` 4 от зоны, иначе `far_us`;
  хотя бы шаг за вызов), ближайший не-SHAPED первым с тем, что ему нужно (`WorldGen.needed`), затем
  террейн и деревья по краю; задание живёт между вызовами (`_gen_job`); когда всё сделано, сканировать
  нечего (`_all_made`), пока зона не сдвинется или чанк не забудут; `make_chunk(key)` — целиком, после
  текущего задания (экран загрузки, инструменты); `forget_far(n)` — до `n` чанков дальше `DROP` (ZONE +
  4) от всех зон (`WorldGen.forget`, изменённые остаются), очередь строится при сдвиге зоны; `gen_us`,
  `work_us` / `take_work()` по видам («terrain», «saved», «trees», «shapes»); `stages_left(reach)` —
  сколько стадий ещё делать (прогресс загрузки).
- `src/shared/game/rules.gd` — правила игры: `free_build`, `tool_wear`, `instant_craft`; `of(dict)`,
  `to_dict` / `from_dict`. На клиенте их ставит страница «Тестирование» (`Settings.apply`), сервер возьмёт
  из конфига.
- `src/server/runner.gd` — узел сервера («ServerRunner», `PROCESS_MODE_ALWAYS`, `process_priority` −10:
  идёт раньше Main) под корнем дерева, не под сценой клиента: переживёт `restart()` сцены (сервер из
  меню, С5). В `_process`: шаги сеанса (часы всегда; персонажи, звери, бури — когда `playing`), затем
  `make_chunks` в бюджетах `near_us` / `far_us`, которые ставит клиент, и `forget_far`. В одиночной
  игре пауза дерева (меню) останавливает шаги, но не генерацию, и та идёт дальше (`PAUSE_ZONE` 7);
  сервер ставит `pausable = false`. Что взял каждый шаг — `took_us`, генерация — `spent_us`
  (`take_spent()` отдаёт раз). Делает и останавливает его `local_host.gd` ([network.md](network.md)).
- `src/client/main.gd` — создаёт правила в `_ready`, сеанс в `start_world` (когда есть мир, со своими
  часами и вещами на клетках) и хост с узлом сервера под `get_tree().root`; в `_process` шагов сеанса
  нет: берёт `host.runner.took_us` в панель F3 (`perf.add`), `host.flush(net)` первым делом игрового
  кадра (события тика), после `chunks.run_jobs(host.runner.take_spent())` ставит бюджеты узлу
  (`_budget_server`: `chunks.gen_budgets()`), в `_exit_tree` останавливает хост (`host.stop()`), если
  узел не `keep`; `actions`, `storms` Main — ссылки на сеансовые, `clock`, `placed`, `wildlife` — копии
  клиента ([network.md](network.md)).

**Кто использует.** Main, `src/server/runner.gd`, `chunk_streamer.gd` (через `game.world_maker`: сеанс
по петле, копия генератора `remote_gen.gd` через сокет — `make_chunk`, `forget_far` при сборке целиком,
`take_work`, `gen_us`, `stages_left`), `tools/profile.gd` (шаги по отдельности, узел сервера
выключен), тесты. Игроки сеанса — серверные
персонажи (`src/server/player.gd`), которых приводит `PlayerLink`; клиент читает `game.actions`,
`game.storms`, `game.rules`, как раньше, персонажа, мастерскую, вещи на клетках, часы и зверей — по их
копиям, а просит у правил через `game.net` — запросами протокола к серверу внутри игры
([network.md](network.md)). Сохранение и страница «Тестирование» пишут в `session.clock` и
`session.placed` (до С4, С5).

**Ограничения.** Тело игрока двигает клиент (`player.gd`), не сеанс: по решению 153 сервер проверит
движение тем же `body.gd` и поправит. Тик узла берёт ввод прошлого кадра (клиент шлёт `input` после
тика), события тика клиент читает в начале своего кадра: копия отстаёт от сервера на кадр. Сделанные
чанки клиент читает из общего мира, по сети они пойдут сообщениями (С3). Число зверей
каждого вида общее на мир (`Wildlife.wanted`), новые появляются у случайного игрока. Погода с улицы
(`real_weather.gd`) пока клиентский узел в общей папке (переедет в `src/server/` на С3).

**Тесты.** `tests/unit/session_test.gd` (`rules`: словарь и обратно, свободная стройка; `session`: тик
двигает время, обоих персонажей и обе мастерские, звери у обоих игроков, ветер по очереди, толчки, уход
игрока; `making`: зона игрока, шаг на крошечном бюджете и задание между вызовами, стадии вокруг зоны в
порядке «свой чанк первым», учёт работы, чанк целиком, забывание дальше `DROP` после ухода, нет игроков
— нечего делать); `tests/save_test.gd` (узел сервера под корнем и уходит со сценой); `tests/unit/body_test.gd` (формы вещей, прочитанные сеансом из моделей, совпадают с моделями);
`tests/unit/net_test.gd` (копии через петлю).
